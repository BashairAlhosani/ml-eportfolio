import numpy as np
import matplotlib.pyplot as plt
from itertools import cycle

from sklearn import svm, datasets
from sklearn.metrics import roc_curve, auc
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import label_binarize
from sklearn.multiclass import OneVsRestClassifier
from sklearn.metrics import roc_auc_score

# Import some data to play with
iris = datasets.load_iris()
X = iris.data
y = iris.target

# Binarize the output
y = label_binarize(y, classes=[0, 1, 2])
n_classes = y.shape[1]

# Add noisy features to make the problem harder
random_state = np.random.RandomState(0)
n_samples, n_features = X.shape
X = np.c_[X, random_state.randn(n_samples, 200 * n_features)]

# shuffle and split training and test sets
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.5, random_state=0)

# Learn to predict each class against the other
classifier = OneVsRestClassifier(
    svm.SVC(kernel="linear", probability=True, random_state=random_state)
)
y_score = classifier.fit(X_train, y_train).decision_function(X_test)

# Compute ROC curve and ROC area for each class
fpr = dict()
tpr = dict()
roc_auc = dict()
for i in range(n_classes):
    fpr[i], tpr[i], _ = roc_curve(y_test[:, i], y_score[:, i])
    roc_auc[i] = auc(fpr[i], tpr[i])

# Compute micro-average ROC curve and ROC area
fpr["micro"], tpr["micro"], _ = roc_curve(y_test.ravel(), y_score.ravel())
roc_auc["micro"] = auc(fpr["micro"], tpr["micro"])

Findings – how parameters change AUC and R²¶

Classification metrics (original cells). The small examples show why one metric is never enough:

  • on the 3-class toy example, accuracy, macro precision and macro recall are 0.50, 0.22 and 0.33;
  • macro, micro and weighted F1 differ (0.27, 0.33, 0.27) because they average over classes differently;
  • the classification report shows a class with 0.00 precision hidden inside an overall accuracy of 0.60.

1. Regularisation and where AUC is measured (breast-cancer data, logistic regression)

C (inverse regularisation) AUC on training data AUC on unseen test data 5-fold CV AUC
0.0001 (very strong regularisation) 0.967 0.950 0.958
0.01 0.985 0.979 0.981
1 0.995 0.991 0.992
100 (very weak regularisation) 0.997 0.987 –
  • Training AUC is always the highest and keeps rising as regularisation weakens. The notebook's own value (0.995) is calculated on the data the model was trained on, so it is optimistic.
  • Test and cross-validated AUC peak around C = 1 and then fall. Weaker regularisation fits the training data better but generalises worse: a small amount of overfitting.
  • Cross-validation gives almost the same ranking as the single test split, but averages over five splits, so it is more reliable for choosing C.

2. Irrelevant features (iris ROC example)

Noise features added 0 20 100 400 800 (the original) 2,000
Micro-average AUC 0.939 0.817 0.806 0.762 0.728 0.667
  • Adding random features steadily pulls AUC towards 0.5 (random guessing). The model starts fitting noise.
  • The effect differs by class. Setosa, which is easy to separate, stays near-perfect until 400 noise features (AUC 0.989). Versicolor is poor even without noise (0.72) and stays around 0.56–0.61. A single overall AUC hides this.

3. R² on the diabetes data (linear regression)

  • More useful features raise R²: 0.04 on the test data with one feature, 0.39 with all ten. But the gap between training and test R² grows (0.55 vs 0.39 with ten features), a sign of overfitting even in a linear model.
  • Noise in the target lowers R²: with noise of sd 100 it falls to 0.09, and with sd 200 to −0.04. The model is then worse than simply predicting the average. The fall is not perfectly smooth (sd 25 gives 0.36 and sd 50 gives 0.39), because with only 133 test patients a single random draw matters.

4. R² can be negative, and errors are not all equal

Predictions R² RMSE MAE
original 0.949 0.61 0.50
always predict the mean 0.000 2.70 2.13
worse than the mean −1.039 3.86 3.75
original with one big error −2.443 5.01 2.75
  • R² = 0 means "no better than the average", and below 0 means worse than the average. It is not bounded below by 0.
  • One large error turns an excellent R² (0.95) into −2.44 and raises RMSE far more (0.61 → 5.01) than MAE (0.50 → 2.75). Squared-error metrics punish large mistakes heavily, so the choice of metric should depend on whether large errors are especially costly.

Problems found in the notebook. The cell headed "RMSE" calculates the MSE (0.375; the RMSE is 0.612). One cell had a stray leading space that stopped it running. The multiclass AUC example no longer runs with the current scikit-learn, and scikit-learn also warns that SVC(probability=True) is deprecated. Small errors like these give wrong numbers without anyone noticing, so evaluation code needs testing like any other code.

Reflection – why this matters professionally¶

Choosing and reporting metrics is an ethical as well as a technical decision. In a medical setting such as the breast-cancer data, a model scored on its own training data, or summarised by one overall number, can look safer than it is. Honest evaluation means:

  • testing on unseen data or with cross-validation;
  • reporting results per class;
  • choosing metrics that match the real cost of each kind of error.

This links directly to my Unit 11 project, where I compared an RBF-SVM (on HOG and colour features) with a custom CNN on CIFAR-10, and evaluated the SVM pipeline with stratified 5-fold cross-validation using accuracy, precision, recall and F1.
