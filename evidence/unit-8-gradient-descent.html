Unit 8 e-Portfolio Activity – Gradient Cost Function¶

Task: read the Mayo (2017) article, then run the tutorial gradient_descent_cost_function.ipynb. Change the number of iterations and the learning rate, and observe how the cost decreases.

This completed copy runs the original first; the original file is unchanged and its code ran as it was. The Experiments section then varies the two settings systematically.

The problem: the five points lie exactly on y = 2x + 3. Gradient descent starts from m = 0, b = 0 and repeatedly moves m and b a small step "downhill" on the cost (the mean squared error, MSE). The learning rate sets the size of each step.

Calculating cost with gradient descent and learning rate¶

  • Change the iteration and learning rate vaules and see the impact on cost.
  • Low iteration values with high learning rate (i.e. big steps) may lead to miss the global minimum
  • Goal is to reach minimum cost with minimum iteration

# code credit:codebasics https://codebasics.io/coming-soon

import numpy as np

def gradient_descent(x,y):
    m_curr = b_curr = 0
    iterations = 100       #change value
    n = len(x)
    learning_rate = 0.08   #change value

    for i in range(iterations):
        y_predicted = m_curr * x + b_curr
        cost = (1/n) * sum([val**2 for val in (y-y_predicted)])
        md = -(2/n)*sum(x*(y-y_predicted))
        bd = -(2/n)*sum(y-y_predicted)
        m_curr = m_curr - learning_rate * md
        b_curr = b_curr - learning_rate * bd
        print ("m {}, b {}, cost {} iteration {}".format(m_curr,b_curr,cost, i))

x = np.array([1,2,3,4,5])
y = np.array([5,7,9,11,13])

The function below repeats gradient_descent() exactly, but records the cost and the (m, b) path instead of printing every line.

import pandas as pd
import matplotlib.pyplot as plt

def run_gd(x, y, iterations, learning_rate):
    m_curr = b_curr = 0.0
    n = len(x)
    costs, path = [], [(0.0, 0.0)]
    with np.errstate(over="ignore", invalid="ignore"):
        for i in range(iterations):
            y_predicted = m_curr * x + b_curr
            cost = (1/n) * np.sum((y - y_predicted) ** 2)
            md = -(2/n) * np.sum(x * (y - y_predicted))
            bd = -(2/n) * np.sum(y - y_predicted)
            m_curr = m_curr - learning_rate * md
            b_curr = b_curr - learning_rate * bd
            costs.append(cost)
            path.append((m_curr, b_curr))
            if not np.isfinite(cost):
                break
    return m_curr, b_curr, np.array(costs), np.array(path)

m, b, costs, _ = run_gd(x, y, 100, 0.08)
print(f"Original settings (100 iterations, learning rate 0.08): m = {m:.4f}, b = {b:.4f}, last cost = {costs[-1]:.6f}")
print("True line: m = 2, b = 3")

3. Why does 0.09 diverge? The stability limit¶

For a mean-squared-error cost, the curvature of the cost surface is fixed by the x values (the Hessian matrix). Gradient descent is only stable if the learning rate is below 2 ÷ (largest curvature):

In [5]:
n = len(x)
H = (2 / n) * np.array([[np.sum(x**2), np.sum(x)], [np.sum(x), n]])
eig = np.linalg.eigvalsh(H)
print("Curvatures (eigenvalues of the Hessian):", eig.round(3))
print(f"Stability limit: learning rate < 2 / {eig.max():.3f} = {2 / eig.max():.4f}")
print(f"Learning rate that balances the two directions (theory): 2 / (largest + smallest) = {2 / (eig.max() + eig.min()):.4f}")
print(f"Condition number (largest / smallest): {eig.max() / eig.min():.0f}  -> one direction is ~70x flatter than the other")

Findings – changing the iterations and the learning rate¶

The original settings (100 iterations, learning rate 0.08) end at m = 2.04 and b = 2.85, with a cost of 0.0041, close to the true line y = 2x + 3. The printout shows that the first steps zig-zag: m jumps 4.96 → 0.50 → 4.45 → 0.89 … before settling down. At 0.08 the learning rate is so large that every step overshoots in the steep direction of the cost surface.

What changing the settings showed

Learning rate Iterations needed to reach a cost below 0.0001 Behaviour
0.001 13,528 very slow, smooth descent
0.01 1,352 slow
0.05 270 fast
0.08 168 (fewest) fastest, with zig-zagging at the start
0.084 550 slower again: the zig-zag decays more slowly
0.0845 12,024 right at the edge: barely converges
0.09 and 0.1 never diverges – the cost explodes (0.1: cost 24,200 after only 10 iterations)
  • Too small a learning rate is safe but slow. With 0.001, even 10,000 iterations leave b at 2.92 instead of 3.
  • Too large a learning rate never reaches the minimum, however many iterations are run. This confirms the notebook's warning that big steps "may miss the global minimum". The best setting is a large rate just below the point where the process becomes unstable.
  • The stability limit can be calculated. The curvatures of the cost surface are 23.66 and 0.34, so gradient descent is stable only for learning rates below 2 ÷ 23.66 = 0.0845. That matches the runs exactly: 0.084 converges and 0.09 diverges.
  • Why both "slow" and "unstable" can happen. One direction of the cost surface is about 70 times steeper than the other, so the cost forms a long, narrow valley. A small learning rate crawls along the flat direction, and a large one bounces across the steep direction (see the path plots). The limit depends on the data: rescaling x would change it. This is one reason inputs are scaled before training.

Link to neural networks (Mayo, 2017). Training a neural network uses exactly this update for every weight: backpropagation calculates each weight's gradient, and the learning rate sets how far the weight moves. In the Unit 7 XOR network, the same trade-off appeared: too small a rate (0.05) had not finished learning within the training time. The difference is that a network has thousands of weights and a cost surface that isn't bowl-shaped, so it has local minima and plateaus as well.
